# Install repository skills

## Intent

Make Spectrum available to every agent that opens the repository, without each contributor installing the plugin, and keep it tied to the repository's pinned CLI.

## Trigger / Entry Points

`spectrum skills install [repository path] [--agent claude|codex|all] [--force] [--dry-run]`. The agent defaults to `all`.

## Preconditions

The target directory exists. Installing the CLI package first is recommended, because the skill runs it.

## Expected Outcome

The command writes one generated skill to `.claude/skills/spectrum/SKILL.md` (Claude Code) and `.agents/skills/spectrum/SKILL.md` (Codex, OpenCode). Each file carries a `Generated by @voyager-fm/spectrum <version>` provenance marker. The command reports created, updated, unchanged or conflict for each agent.

## State Changes

Creates or replaces only the selected skill files. A file that carries the marker is updated in place. `--dry-run` writes nothing.

## User-visible Feedback

JSON with `ok`, `dryRun` and one entry per agent with its path, outcome and, for a conflict, the reason.

## Edge Cases / Failure Handling

A file at a skill path without the marker is a conflict unless `--force` is given. A link or directory at the path is always a conflict. Any conflict writes nothing for any agent and exits with status 1. An unknown `--agent` value exits with status 1. Writes never follow a link outside the repository.

## Acceptance Criteria

- [ ] **AC-1:** The command writes the same skill, with the version marker, to both agent paths, and a repeat run reports unchanged.
- [ ] **AC-2:** A file Spectrum installed earlier is updated in place, and `--agent` limits the write to one agent.
- [ ] **AC-3:** A file without the marker is not replaced without `--force`, and any conflict leaves every skill path untouched.
- [ ] **AC-4:** The installed skill passes Agent Skills frontmatter rules and runs `node_modules/.bin/spectrum`.

## Permissions / Dependencies

Writes to the local working tree only. The installed skill grants agents no authority beyond running the read-only check and list commands, and running setup commands when the user asks.

## Observability / Analytics

The marker records which package version wrote each file, and the dashboard reads it from a pinned commit.

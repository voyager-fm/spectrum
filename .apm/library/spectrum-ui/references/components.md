# Components and styling

## Layers
1. `src/components/ui/*`: shadcn/ui primitives (style `base-nova`, Base UI, `neutral`). Generated by the CLI; do not restyle them per page.
2. `src/components/dashboard.tsx`: Spectrum compositions built on those primitives. Pages use these first.
3. Pages: Tailwind utility classes for layout only (`grid`, `gap-*`, `mt-*`, `rounded-xl border`).

Add a shadcn primitive from `apps/web`: `pnpm dlx shadcn@4.23.0 add <name> -y`. Already installed: alert, badge, button, card, empty, separator, table. Add a composition to `dashboard.tsx` only when a second page needs the same structure.

shadcn files import `cn` from the `cn` package (published by shadcn) and use the `@/` alias for `src/`. Spectrum's own files keep relative imports with explicit `.ts`/`.tsx` extensions; `@/components/ui/*` and `@/lib/utils` are the exceptions.

## Spectrum compositions (`src/components/dashboard.tsx`)
| Component | Use |
| --- | --- |
| `PageHead({ title, description })` | First element of every page. The description says what the page shows and, when relevant, what it does not prove. |
| `LoadErrors({ errors })` | Directly after `PageHead` on every page that calls `loadDashboard()`. Destructive `Alert`; renders nothing without errors. |
| `StatusBadge({ tone })` | All status labels. Tones below. |
| `StatCard({ title, value, children })` | Summary metric; `children` is the muted footnote. |
| `Section({ title, description })` | Titled block below the first content (`mt-10`). |
| `Mono` | Inline code for IDs, paths and commands. |
| `EmptyNotice` | Successful load with zero items. |
| `Planned({ title, upcoming, children })` | The only way to show an unimplemented capability. Dashed container, "Not implemented" badge, reason and planned items. |

## StatusBadge tones (ink)
| Tone | Style | Meaning | Current uses |
| --- | --- | --- | --- |
| `ok` | solid ink (`bg-foreground`) | verified good state | check passed, no findings |
| `bad` | destructive (only color) | failure needing action | check failed, finding codes, could not run |
| `planned` | dashed outline, muted | not implemented, not run, stale | Not implemented, AC "Not run" |
| `info` | secondary fill | configuration fact | mode, integration enabled, rule in repository |
| `neutral` | outline | draft or untracked | draft, Not tracked, None configured |

Do not use `ok` for something that was not checked, such as a document marked approved but never verified against code.

## Tables and lists
Wrap `Table` in `<div className="rounded-xl border">`. Right-align numeric columns with `tabular-nums`. Use `whitespace-normal` on free-text cells. Link the identifier cell (`font-mono text-xs`) to the detail page.

## Tokens and theme
- Colors come from shadcn CSS variables in `src/app/globals.css` (`--background`, `--foreground`, `--muted(-foreground)`, `--border`, `--brand`, `--primary`, `--destructive`, `--warning`, `--sidebar-*`). Use Tailwind classes that reference them (`bg-muted`, `text-muted-foreground`, `bg-brand`). Never write literal colors; the `BrandMark` gradient is the one exception.
- Only `--brand` (and the tokens that follow it: `--primary`, `--ring`, `--sidebar-primary`, `--chart-*`), `--destructive` and `--warning` carry chroma. Keep every other token at zero chroma; see design.md.
- Dark mode follows `prefers-color-scheme` through `@custom-variant dark`. There is no `.dark` class or theme toggle.
- Fonts: Geist (`--font-sans`) and Geist Mono (`--font-mono`) via `next/font/google` in `layout.tsx`.
- Focus rings come from shadcn primitives and `focus-visible:ring-*` on custom links. Do not remove them.

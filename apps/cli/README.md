# @voyager-fm/spectrum

Deterministic command line for repository product specs in `.spectrum/`. It checks specs, creates a starter bundle and installs the Spectrum agent skill into a repository. It needs no model credentials and makes no network requests.

> Not yet published to npm. Until it is, build a tarball from this repository with `pnpm --filter @voyager-fm/spectrum pack` and install that file.

## Install in a repository

```sh
npm install --save-dev @voyager-fm/spectrum
npx --no spectrum init             # .spectrum/config.json and a connected starter bundle
npx --no spectrum skills install   # .claude/skills/spectrum and .agents/skills/spectrum
npx --no spectrum check
npx --no spectrum status           # what is set up, what is missing, which skill is outdated
```

Always pass `--no` to `npx`. The unscoped npm package `spectrum` is unrelated, so a bare `npx spectrum` could download it.

## Commands

| Command | Writes | Result |
| --- | --- | --- |
| `check [path] [--profile p.json] [--format json\|text\|github]` | nothing | Structural result; JSON by default, exit 1 on structural errors |
| `list [path] [--profile p.json] [--format json\|text]` | nothing | Interaction specs; JSON by default |
| `init [path] [--name project] [--dry-run]` | the starter bundle | Files written, conflicts and a check summary |
| `skills install [path] [--agent claude\|codex\|all] [--force] [--dry-run]` | agent skill files | One outcome per agent: created, updated, unchanged or conflict |
| `status [path]` | nothing | Configuration, package and agent skill state, skill version drift and the next commands; exit 0 only when ready |
| `--version` | nothing | The package name and installed version |

`init` is all-or-nothing. When any starter path already exists, including `.spectrum/config.json`, it reports the conflicts and writes nothing. Starter values Spectrum cannot know are `TBD`, and `check` reports them as warnings until a person decides them. Nothing in the starter is approved or verified.

`skills install` writes the same skill for Claude Code (`.claude/skills/spectrum/SKILL.md`) and Codex/OpenCode (`.agents/skills/spectrum/SKILL.md`). The skill runs `node_modules/.bin/spectrum`, the version the repository pins. Files carry a `Generated by @voyager-fm/spectrum <version>` marker. Re-running the command updates marked files. It refuses to replace any other file unless you pass `--force`, and a conflict for one agent writes nothing for any agent.

Neither command writes outside the repository root or through a symbolic link that leaves it.

## Output formats

## Create specification drafts

`spectrum new <kind> --describe` lists the canonical template inputs without writes.
Create a JSON object of string values, then run
`spectrum new <kind> [path] --values values.json [--out drafts/file.md] [--dry-run]`.
Kinds include interaction, contract, flow, adr, feature (three companion documents),
and explicit engine catalog IDs. `--out` is for single templates only. Dry runs
return the complete plan; existing files and links are never overwritten. Creation
does not update inventories/configuration or imply validation or approval. Review
configured document mappings and run `spectrum check` afterward.

## Diagnose local setup

`spectrum status [path]` retains its existing setup JSON and readiness exit code.
`spectrum doctor [path] [--format json|text]` additionally checks local package/skill
evidence and runs the real structural checker when configuration can be read.
Missing/blocked checks are reported explicitly. It never repairs files, installs
packages, executes customer binaries or calls a network service. Observed manifest
versions and declared package ranges remain separate; active CLI origin stays unknown
unless a caller supplies evidence. Errors fail the command; warnings remain visible.

### Check and list output

JSON remains the default and preserves the existing result object (`check`) or raw
spec array (`list`). Use `--format text` for structural summaries and readable findings
or spec/acceptance summaries. Document review states and checked AC annotations are
not implementation or executed-test evidence.

`check --format github` emits escaped GitHub Actions error/warning annotations and a
structural summary. It makes no API requests and retains exit 1 on structural errors.
Warnings remain visible even when the exit code is 0. GitHub format is not supported
for `list`. Progress and failures do not become synthetic successful results.

```sh
node_modules/.bin/spectrum check --format text
node_modules/.bin/spectrum list --format text
node_modules/.bin/spectrum check --format github
```

## Build

`pnpm --filter @voyager-fm/spectrum build` writes `dist/spectrum.mjs`. This is one self-contained Node 20+ script with the spec templates embedded. `pack` runs the same build first.
